# 纳指 100 公开渠道实况雷达

部署在 GitHub Actions 的场外 QDII 基金监控器。它跟踪国内公募中名称含“纳斯达克 100”的场外 QDII 基金与 ETF 联接基金，并把**已接入代销渠道**当前页面展示的申购、定投和日限额发送到 PushPlus。

> 第一阶段的已接入渠道为 **天天基金**。支付宝、理财通、基金公司直销和其他销售平台均不会被推断；卡片只会报告来源页面实际展示的渠道状态。

## 推送内容

- 天天基金当前页面的申购状态：开放、限额、暂停或待核验；
- 定投状态：可定投、不可定投或待核验；
- 该渠道显示的日累计申购上限；暂停申购时即使页面还保留旧限额数字，也显示 `—`，不暗示仍可买；
- 与上一次渠道页面相比的申购状态、定投状态、额度变化；
- 基金代码、渠道名称和数据口径说明。
- 基金公司最新适用公告的交叉核验结果：一致、有差异或待核验。公告不会覆盖渠道页面状态。

同一产品中状态、定投和额度一致的不同份额会合并展示。场内 ETF 自动排除，ETF 联接基金保留。

## 运行方式

工作日北京时间 **08:00–22:30**，每 30 分钟检查一次。每天首次成功检查发送一份完整汇总；之后仅在渠道页面状态、额度或定投状态变化时推送。

GitHub 的定时任务可能延迟执行，因此“检查时间”表示实际完成抓取的北京时间，不承诺整点到达。

## 首次启用

1. 在仓库 **Settings → Actions → General** 中允许工作流读写仓库内容；它会保存 `state/last_snapshot.json` 以识别变化。
2. 在 **Settings → Secrets and variables → Actions** 新建仓库 Secret：

   ```text
   PUSHPLUS_TOKEN
   ```

3. 打开 **Actions → 纳指100公开渠道实况雷达**，选择 **Run workflow** 运行一次。首次只有全部基金页面都成功读取时才会建档并推送；这样不会用不完整数据建立基线。

PushPlus Token 不会写入代码、日志或快照。

## 数据口径与安全规则

- 基金池来自公开基金代码表：名称命中“纳斯达克 100”或“纳指 100”，且属于 QDII 或“海外”基金类型的场外基金都会纳入；不因代码表遗漏 `QDII` 字样而排除（例如国泰 160213）。新发基金也会随代码表更新自动发现。
- 当前已人工审计的 60 个场外代码被记录为完整性基线。若上游数据、筛选规则或命名变化导致其中任何一只消失，任务会停止并报出缺失代码，绝不推送一份悄悄缺项的清单；基金正式清盘、合并或改名时再人工更新这份基线。
- 当前交易状态来自天天基金公开详情页中的“申购状态、定投状态、日累计申购限额”字段，而非公告推断。
- 每只基金还会读取最近一条适用于非直销口径的基金公告作背景核验。公告与天天基金页面不同会明确提示“公告有差异”，并保留天天基金作为该渠道的主状态。
- 请求有全局节流和重试；单页失败时保留上一次可信状态，不把网络错误报成“暂停”。首次建档只要有页面失败就不发送。
- 当前页面显示“暂停申购”时，程序不会把仍显示的日限额当作可购买金额。
- 只有在来源页面和渠道明确时才报告“开放”。这不代表支付宝、理财通或基金公司直销也开放。

## 后续接入

项目采用“每个渠道独立一行”的设计。当前已经有“天天基金渠道页 + 基金公司公告核验”两层。接入新的、可核验的渠道后，会在卡片中单独标示来源，不会用天天基金状态替代支付宝或理财通状态。

## 本地校验

项目只使用 Python 标准库：

```bash
python -m unittest discover -s tests -v
python src/main.py --dry-run --force-digest
python src/main.py --preview
```

`--dry-run` 会读取公开页面并生成推送卡片，但不会发送；`--preview` 只重建最近一次快照。
